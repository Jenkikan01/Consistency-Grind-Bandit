	Network Server Listening to them:
		Service/Network Server is actively waiting on a specific port or address to receive incoming connection
		requests from those clients/devices
	So a port is a way for a device to establish a connection/connect to a server by acting as a doorway
 
	Netstat = is used inside the machine/server to find all ports currently listening on that computer
		  Thus showing active connections that are open
	Nmap = is used from the outside to knock on a server's ports across a network to knock on a servers port 
		- It tells which doors are open (Listening)
		- It tells what specific software is behind each door
		- Tells whether a firewall is blocking them
	Handshake = establishing a connection

	openssl s_client is identical to nc (netcat)
		The difference: nc sends the messages in an unencrypted manner while openssl s_client wraps the
			data and information in encryption in SSL/TSL automatically
		In other words it is a netcat but with built in encryption

	openssl s_client use cases:
		Talking to encrypted servers manually = opens a text connection to a server and encrypts in TLS/SSL
			encryption
		Inspecting SSL/TLS certificates = used in checking websites security certificate expiry, issuer and
			encryption versions the server supports
		Debugging secure connections = if an app or website is failing to connect securely, openssl s_client is
			used to pinpoint the exact handshake details and pinpoint the encryption failure

	So openssl s_client sets up an encrypted session between the server and my machine, and closes when EOF is reached (like pressing Ctrl + D, or right after echo finishes feeding the password).
	In default mode (without -quiet or -ign_eof), openssl inspects the very first character of each line before sending anything, and intercepts these hotkeys instead of passing my text to the server:
		Q = Ends/closes the session completely (DONE).
		R = Refreshes/renegotiates the entire SSL handshake from scratch without hanging up (RENEGOTIATING — TLS 1.2 and below).
		k = Swaps only my outgoing encryption key to a fresh one without hanging up (KEYUPDATE — TLS 1.3).
		K = Swaps my outgoing key AND forces the server to swap its key too, keeping the session open (KEYUPDATE — TLS 1.3).
		Because R, k, and K keep the session alive while swallowing the line to run those TLS updates,
			you could keep sending passwords that start with them over and over without 
			disconnecting—and the server would never actually receive the password until you add -quiet.
